Dépannage

Les messages ci-dessous sont ceux que l'on rencontre le plus souvent. Chacun indique ce qu'il signifie et quoi faire.

« no aarshi.toml in this folder »

Vous n'êtes pas dans un projet créé par aarshi setup. Placez-vous d'abord dans le dossier du projet (celui qui contient aarshi.toml), puis relancez la commande.

« Tailwind is not wired »

aarshi status signale ce message quand les styles ne seraient pas compilés. Utilisez l'une des deux façons de brancher Tailwind CSS 4 :

  • dans next.config.ts, le loader Turbopack @tailwindcss/turbopack pour les fichiers *.css ;
  • ou un fichier postcss.config.* qui utilise le plugin @tailwindcss/postcss.

Une seule suffit.

« use -s <section> <page> for a section, -p <page> for a page »

aarshi add <nom> sans option ne sait pas quoi ajouter. Choisissez l'option : -p pour une page, -s pour une section, -c pour un composant. Ou lancez aarshi add seul et répondez au menu.

« page `…` does not exist »

Vous avez demandé une section dans une page absente de views/. aarshi demande s'il faut la créer : répondez y pour créer la page et y ajouter la section, ou n pour arrêter sans rien modifier.

Valeurs vides signalées comme todo

Un dictionnaire contient des clés sans texte, typiquement après aarshi add-lang. Ce n'est pas une erreur, et le code de sortie reste 0. Remplissez les valeurs dans lib/i18n/dictionaries/<code>.ts. Lancez aarshi status --errors-only pour les masquer pendant le travail.

« missing components/ui/… »

Les composants d'interface attendus par la clé ui d'aarshi.toml ne sont pas là. Ils sont écrits par aarshi setup : shadcn installe button et button-group, et Base UI les écrit à partir de ses propres modèles. Restaurez le fichier manquant depuis un autre projet créé avec la même valeur de ui, ou lancez aarshi setup dans un nouveau dossier et copiez le fichier.

Code de sortie 2 avec aarshi status

Le projet ne peut pas être lu. Le message sur la sortie d'erreur indique la cause : aarshi.toml est absent, illisible, ou contient une clé inconnue. Corrigez ce fichier, puis relancez la vérification.

La documentation ne s'ouvre pas

aarshi docs écrit les pages dans un dossier temporaire et affiche son chemin. Si le navigateur ne s'ouvre pas tout seul, ouvrez à la main le fichier index.html du dossier en ou fr de ce chemin.

Toujours bloqué ?

Lancez aarshi status --json et gardez la sortie : elle liste chaque constat avec le nom de sa règle, ce qui est la première information à donner quand on demande de l'aide. Les règles sont listées dans le fichier CONVENTIONS.fr.md du dépôt.
